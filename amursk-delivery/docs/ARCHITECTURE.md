# Архитектура «Амурск»

## Целевая схема

Житель открывает адаптивный сайт/PWA на GitHub Pages или другом статическом хостинге → HTTPS API на российской VPS/облачной VM → PostgreSQL на приватной сети. Фото/вложения — объектное хранилище в российском регионе, если это требуется выбранной моделью обработки данных. DNS и TLS — отдельные настройки домена и reverse proxy (Nginx/Caddy).

## Компоненты в этом пакете

- Frontend: существующий vanilla HTML/CSS/JS PWA. Сейчас демонстрационные операции локальны.
- API: Node.js 20 + Express, JWT, bcrypt, Helmet, CORS, rate limit.
- DB: PostgreSQL 16; SQL-схема пользователей, объявлений, диалогов, сообщений, откликов на задания и отзывов.
- Deployment: Docker Compose. База не публикует порт наружу; API слушает localhost:3000 хоста и предполагает reverse proxy.

## Потоки

1. Регистрация: email + пароль → bcrypt hash → users → JWT.
2. Вход: проверка bcrypt → JWT на 7 дней.
3. Объявление: авторизованный пользователь создаёт запись listings.
4. Диалог: участник создаёт conversation и membership; читать/отправлять сообщения могут только участники.
5. Профиль: наружу возвращается имя, публичный район, био, аватар и обложка. Домашний адрес не выдаётся.

## Что необходимо до публичного запуска

- Интегрировать frontend с API, убрать конфликтующее localStorage-поведение для авторизованных пользователей.
- Добавить подтверждение email, восстановление пароля, SMS-провайдера и OAuth-провайдеры (Google/VK ID) с серверной проверкой callback/state/PKCE.
- Добавить WebSocket или SSE для доставки новых сообщений, уведомления и push.
- Добавить роли модератора/администратора, жалобы, блокировки, скрытие контента, лимиты публикаций, журнал событий.
- Добавить защищённую загрузку изображений: MIME sniffing, размер, антивирусная проверка, генерация безопасных имён, приватные/публичные ACL.
- Добавить подтверждение завершения заказа обеими сторонами до счётчика выполненных работ и отзывов.
- Настроить ежедневные резервные копии, тест восстановления, метрики, алерты, лог-ротацию и обновления безопасности.
- Провести нагрузочное, функциональное и security-тестирование.

## Персональные данные и безопасность

Не публиковать точный домашний адрес. В публичном профиле — только добровольно указанный район. Точный адрес (если действительно нужен для выполнения заказа) передавать только после согласия и только выбранному исполнителю. Определить оператора персональных данных, цели и сроки обработки, правовые основания, политику конфиденциальности, порядок удаления/выгрузки данных и процедуры инцидентов. До выбора региона облака и схемы резервного копирования получить юридическую консультацию по применимому законодательству РФ и странам фактического размещения/доступа.

## Не включено

В этом пакете нет созданного Cloud.ru аккаунта/виртуальной машины, купленного домена, оплаченных SMS, OAuth credentials, реального TLS-домена и подключённых внешних сервисов. Ничего из этого нельзя безопасно создать без аккаунта владельца, выбора тарифа и секретов, которые вводит сам владелец в панели провайдера.
