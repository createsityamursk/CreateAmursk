# Размещение на Cloud.ru — пошаговый план

Это инструкция, не отчёт о выполненном развёртывании: облачный аккаунт и ресурсы не создавались.

## Перед созданием ресурсов

1. Войдите в Cloud.ru под аккаунтом владельца проекта.
2. Проверьте действующие условия тестового периода/бонусов, ограничения для физлиц и список доступных регионов. Не считать бесплатный период гарантированным, пока он не отображён в вашем личном кабинете.
3. Для пользовательской базы выберите российский регион, если это соответствует юридической модели обработки данных проекта.
4. На старте ориентир — Linux VM, 2 vCPU и 4 GB RAM как более комфортный пилотный минимум для API + контейнеров; PostgreSQL предпочтительно отдельным managed-сервисом или отдельной VM при росте. Фактический тариф проверить калькулятором Cloud.ru перед созданием.

## Рекомендуемый стартовый вариант

- Одна Linux VM для Docker Compose API + PostgreSQL на пилоте.
- Внешний доступ только к 80/443 через reverse proxy; порт PostgreSQL наружу не открывать.
- SSH только по ключу, запрет root password login, firewall/security group.
- Отдельный том/диск и ежедневные резервные копии вне основной VM.
- Статический фронтенд оставить на GitHub Pages; указать API URL в конфигурации фронтенда после интеграции.

## Запуск

1. Создайте VM Ubuntu LTS в панели Cloud.ru.
2. Подключитесь по SSH-ключу.
3. Установите Docker Engine и Compose plugin по официальной инструкции Docker для выбранной Ubuntu.
4. Скопируйте папку проекта на VM (например, через `scp` или приватный Git-репозиторий).
5. Создайте `.env` из `.env.example`, сгенерируйте секреты локально командой `openssl rand -hex 32`; не отправляйте секреты в чат и не коммитьте `.env`.
6. Настройте `CORS_ORIGIN` на точный HTTPS-адрес фронтенда.
7. Запустите `docker compose up -d --build`.
8. Установите Nginx/Caddy как reverse proxy, подключите домен и TLS, проксируйте `https://api.домен` на `127.0.0.1:3000`.
9. Проверьте `/api/health`, регистрацию тестового пользователя, вход, создание объявления, диалога и сообщения.
10. Настройте резервное копирование и проверьте восстановление на отдельной тестовой БД.

## Перед открытием регистрации всем

Обязательно: подтверждение email/телефона, восстановление пароля, антиспам, модерация, жалобы, политика обработки персональных данных, согласия, контакт оператора, ограничения доступа к адресам, мониторинг, резервные копии и security review.
