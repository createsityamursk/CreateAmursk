# АМУРСК — городской портал Амурска

Пакет передачи проекта: фронтенд-прототип + исходники серверного API + PostgreSQL-схема + Docker Compose + инструкции + история решений и рабочие промпты.

## Состав

- `frontend/amursk-city-community/` — текущая веб/PWA-версия. Запуск локально: `python -m http.server 8000` из этой папки.
- `backend/` — Node.js/Express API и PostgreSQL schema. Реализованы базовые REST-маршруты регистрации/входа по email+паролю, профиль, объявления, создание диалога по объявлению и сообщения.
- `docker-compose.yml` — запуск API и PostgreSQL одной командой.
- `.env.example` — список секретов и переменных окружения.
- `docs/ARCHITECTURE.md` — архитектура и границы текущей реализации.
- `docs/DEPLOY_CLOUD_RU.md` — план размещения на Cloud.ru.
- `docs/USER_GUIDE.md` — инструкция для владельца/администратора.
- `docs/PROJECT_HISTORY_AND_PROMPTS.txt` — история требований и сохранённые промпты для продолжения работы.

## Быстрый локальный запуск backend

Требуется Docker Engine + Docker Compose.

1. Скопировать `.env.example` в `.env`.
2. Заменить `POSTGRES_PASSWORD` и `JWT_SECRET` длинными случайными секретами (не менее 32 символов для JWT).
3. Указать фактический HTTPS origin сайта в `CORS_ORIGIN`.
4. Из корня проекта выполнить `docker compose up -d --build`.
5. Проверить `http://localhost:3000/api/health`.
6. Остановка: `docker compose down`. Данные БД сохраняются в Docker volume `pgdata`; `docker compose down -v` удалит базу безвозвратно.

## API endpoints

- `POST /api/auth/register` — email, password (10+ символов), displayName.
- `POST /api/auth/login` — email, password.
- `GET /api/me` и `PATCH /api/me` — авторизованный профиль.
- `GET /api/listings` — публичная лента.
- `POST /api/listings` — создать объявление (Bearer JWT).
- `POST /api/conversations` — создать диалог по `listingId`.
- `GET /api/conversations` — диалоги текущего пользователя.
- `GET /api/conversations/:id/messages` — получить сообщения.
- `POST /api/conversations/:id/messages` — отправить `{ "body": "..." }`.

## Важные ограничения — прочитать до запуска для реальных пользователей

1. Фронтенд пока не переключён на API: он продолжает использовать localStorage для демонстрационных данных. Backend — отдельный подготовленный серверный слой; интеграция интерфейса с API является следующим инженерным шагом.
2. Email-адрес сейчас не подтверждается. Нет сброса пароля, подтверждения телефона/SMS, Google OAuth или VK ID/Mail.ru OAuth. Не рекламировать их как работающие.
3. Сообщения через API сохраняются в PostgreSQL, но доставка не realtime (нет WebSocket/SSE/push), нет статуса прочтения и вложений.
4. Нет административной панели, жалоб, блокировок, антиспама, CAPTCHA, модерации, аудита действий, резервного копирования и мониторинга.
5. Не хранить открытые домашние адреса в публичном профиле. В этой схеме private_address — закрытое поле, API профиля его не выдаёт; интерфейс и отдельные права доступа ещё требуется реализовать.
6. Схема БД — стартовая, перед production обязательны миграции, тесты, проверка безопасности и юридическая проверка обработки персональных данных.
7. Не помещать `.env`, JWT secret, пароль БД, OAuth client secret или ключ SMS в GitHub и клиентский JavaScript.

## Лицензирование и передача заказчику

В пакет включены исходники, конфигурационные шаблоны и документация. Перед перепродажей/передачей заказчику проверьте права на фотографии, шрифты и сторонние материалы фронтенда; замените внешние изображения на лицензированные/собственные. Уточните договором право использования и сопровождения. Не передавайте заказчику реальные секреты из `.env`.
