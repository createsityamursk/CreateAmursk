ПРОЕКТ «АМУРСК» — ИСТОРИЯ РЕШЕНИЙ И ПРОМПТЫ ДЛЯ ПРОДОЛЖЕНИЯ
Версия документа: 1.0
Дата сборки пакета: 21.11.2026

ВАЖНО О ПОЛНОТЕ
Это структурированная история требований и решений, восстановленная по доступной переписке текущего проекта. Это не дословная выгрузка всего чата: часть голосовых сообщений была автоматически распознана фрагментарно, поэтому документ сохраняет смысловые требования, а не выдумывает отсутствующие дословные реплики.

1. ИДЕЯ И ЦЕЛЬ

Пользователь хочет создать городскую платформу для жителей Амурска (Хабаровский край), объединяющую городскую доску объявлений и сервис взаимопомощи. Это не классическая социальная сеть с бесконечными личными постами. Основной сценарий — зайти, быстро посмотреть объявления жителей, предложить/найти вещь, работу, услугу, транспорт или помощь, открыть профиль автора и связаться с ним.

Рабочая идея/позиционирование: «Амурск — город рядом», «Наш Амурск».

2. ОСНОВНЫЕ ТРЕБОВАНИЯ ПОЛЬЗОВАТЕЛЯ

- Сайт должен хорошо выглядеть на компьютере и телефоне.
- Нужна устанавливаемая на Android мобильная версия (PWA на первом этапе).
- Визуальный стиль: тёмная палитра, аккуратные градиенты, современные карточки, подсветка интерактивных элементов; сохранить местный городской характер, не копировать Instagram буквально.
- Главный раздел — лента объявлений, похожая по удобству на социальную ленту, но по смыслу это доска объявлений.
- Четыре главные категории, которые пользователь отдельно выделил: «Отдам даром», «Заработать/Подработка», «Продам», плюс прочие необходимые городские разделы. В прототипе дополнительно присутствуют «Потеряно», «Найдено», «Транспорт», «Услуги».
- Подкатегории должны соответствовать каждой категории, чтобы пользователь при создании объявления не публиковал всё в одну общую ленту.
- В «Подработке» нужны задания вроде разнорабочего, помощи с переездом/погрузкой, уборки, ремонта, помощи по дому, доставки и разовых поручений. Заказчик указывает оплату (например, 200–500 рублей), исполнитель откликается, заказчик выбирает исполнителя.
- Добавить транспорт/такси: поиск такси, попутчиков, грузоперевозок.
- Объявления должны содержать заголовок, описание, категорию/подкатегорию, цену или вознаграждение, район/место, автора, дату, фотографии и кнопку связи.
- Регистрация и личные профили. Пользователь хочет вход по номеру телефона, а также рассматривал Google, Mail.ru и другие способы. Mail.ru рассматривать через VK ID/OAuth только после проверки актуальных условий провайдера.
- Профиль: имя, аватар, обложка/шапка, описание/статус, район, объявления, количество выполненных заказов.
- Нужны реальные личные сообщения между разными пользователями, не имитация на одном устройстве.
- Выполненные заказы и рейтинг должны считаться только после подтверждения результата сторонами, не просто после публикации объявления.
- Пользователь просил сделать городскую идентичность: фотографии Амурска, историческая справка, городские места, архивные снимки и воспоминания жителей.
- Раздел «Наш Амурск»: фотогалерея, история города, старые фотографии, воспоминания, подписи с годом/районом, комментарии и публикации жителей. Для общего доступа нужна серверная база и модерация.
- Точный домашний адрес нельзя бездумно показывать всем. Публично лучше показывать район; точный адрес, если он нужен для заказа, раскрывать только выбранному исполнителю с согласия пользователя.
- Пользователь хочет получить переносимый пакет файлов, чтобы можно было передать проект заказчику/развивать дальше, и отдельный текстовый документ с историей, инструкциями и промптами.

3. ПРЕДЫДУЩИЕ ТЕХНИЧЕСКИЕ РЕШЕНИЯ И ВЕРСИИ

- Изначально обсуждался MVP на TypeScript + Vite + Phaser для другой игры; к текущему проекту «Амурск» этот игровой стек не относится.
- Для «Амурска» был создан статический HTML/CSS/JavaScript прототип с PWA-манифестом и service worker.
- Прототип развивался от простой доски объявлений к тёмной городской платформе.
- В версии City Community v3 присутствуют категории: «Отдам даром», «Подработка», «Продам», «Потеряно», «Найдено», «Транспорт», «Услуги»; подкатегории, поиск, сортировка, создание объявления, профиль, демонстрационные диалоги, «Наш Амурск».
- Фронтенд v3 использует localStorage. Поэтому данные существуют только в одном браузере и не синхронизируются с другими людьми.
- В ранней версии «Наш Амурск» были описаны исторические даты: 19 июня 1958 года — прибытие первостроителей/день рождения города; 28 августа 1958 года — присвоение названия Амурск; 27 декабря 1973 года — преобразование рабочего посёлка в город. Исторический контент необходимо перепроверять по официальным источникам перед публикацией как музейную справку.
- В качестве инфраструктурной идеи обсуждались Cloud.ru, российская VPS, PostgreSQL. Бесплатные/тестовые условия облачного провайдера должны проверяться непосредственно в аккаунте перед заказом; тестовый период не гарантирован.
- В текущем пакете добавлен серверный фундамент: Node.js/Express, PostgreSQL, JWT, Docker Compose. Он НЕ развёрнут в Cloud.ru и пока НЕ подключён к интерфейсу.

4. ЧТО ВХОДИТ В ТЕКУЩИЙ ПАКЕТ

- frontend/amursk-city-community — статический фронтенд/PWA City Community v3.
- backend — Express API, регистрация и вход по email+паролю, профиль, чтение/создание объявлений, диалоги и сообщения через REST.
- backend/db/schema.sql — таблицы users, listings, conversations, conversation_members, messages, job_applications, reviews.
- docker-compose.yml — контейнеры API и PostgreSQL.
- .env.example — шаблон переменных окружения.
- README.md, docs/ARCHITECTURE.md, docs/DEPLOY_CLOUD_RU.md, docs/USER_GUIDE.md.

ОГРАНИЧЕНИЯ ТЕКУЩЕГО ПАКЕТА:
- Интерфейс ещё не интегрирован с API: он продолжает использовать локальное хранилище.
- Нет подтверждения email, восстановления пароля, SMS OTP, Google OAuth, VK ID/Mail.ru OAuth.
- Сообщения API сохраняются в PostgreSQL, но пока нет realtime-доставки, push-уведомлений, вложений и статуса прочтения.
- Нет готовой панели модерации, жалоб, блокировок и антиспама.
- Не создан Cloud.ru аккаунт, VM, домен, TLS, SMS-подключение или OAuth credentials.
- Пакет — инженерная основа для разработки и тестирования, а не сертифицированный production-сервис.

5. ПЛАН РАЗВИТИЯ (РЕКОМЕНДУЕМЫЙ ПОРЯДОК)

Этап A — инфраструктура и API:
1. Выбрать регион и тариф Cloud.ru или другого российского провайдера в аккаунте владельца.
2. Развернуть Linux VM, Docker, reverse proxy, TLS.
3. Запустить PostgreSQL и API; настроить firewall, секреты, резервное копирование.
4. Протестировать API и восстановление БД.

Этап B — интеграция фронтенда:
1. Вынести API URL в конфигурацию фронтенда.
2. Добавить регистрацию/вход, хранение токена безопасным способом, выход и обновление сессии.
3. Перевести ленту/профиль/объявления с localStorage на API.
4. Реализовать список диалогов и сообщения с polling или WebSocket/SSE.

Этап C — способы входа:
1. Подтверждение email и сброс пароля.
2. SMS OTP через выбранного провайдера.
3. Google OAuth.
4. VK ID, если подходит для Mail.ru-аудитории и условия приложения позволяют такой вход.

Этап D — городские функции:
1. Загрузка фото в объектное хранилище.
2. Подкатегории и фильтры по районам.
3. Отклики на подработку и выбор исполнителя.
4. Статусы заказа: опубликован → отклики → исполнитель выбран → в работе → завершён обеими сторонами.
5. Отзывы после подтверждения завершения.
6. Раздел «Наш Амурск»: фотоархив, годы/районы, воспоминания, комментарии, модерация.

Этап E — безопасность и запуск:
1. Жалобы, блокировки, модерация, rate limiting/CAPTCHA.
2. Проверка доступа к личным сообщениям и закрытым данным.
3. Политика конфиденциальности, пользовательское соглашение, согласия, сроки хранения и удаление аккаунта.
4. Тестирование безопасности, нагрузочное тестирование, мониторинг и backup restore.

6. СОХРАНЁННЫЕ РАБОЧИЕ ПРОМПТЫ

Промпт 1 — роль и цель продукта:
«Выступай как ведущий full-stack разработчик и архитектор продукта. Развивай проект “Амурск — город рядом”: городская платформа для жителей Амурска, объединяющая доску объявлений, подработку, услуги, транспорт, личные сообщения и локальную историю города. Сохраняй существующий проект и его работающие функции. Не выдавай прототип за production.»

Промпт 2 — визуальный стиль:
«Создай премиальный современный тёмный интерфейс для городской платформы Амурска. Палитра графитовая, глубокие синие и речные бирюзовые оттенки, аккуратные градиенты, мягкая подсветка hover/focus, качественная типографика, понятная мобильная навигация. Не копируй Instagram: используй удобство визуальной ленты, но сохрани характер городской доски объявлений. Интерфейс должен быть адаптивным и доступным.»

Промпт 3 — объявления:
«Сделай категории “Отдам даром”, “Подработка”, “Продам”, “Потеряно”, “Найдено”, “Транспорт”, “Услуги”. Для каждой категории предусмотрены релевантные подкатегории. Форма публикации должна валидировать поля и поддерживать фото, цену/вознаграждение, район, описание и контакт через внутренний чат. Добавь поиск, фильтр, сортировку и карточку объявления.»

Промпт 4 — подработка и заказы:
«Реализуй безопасный сценарий разовых заданий: заказчик публикует задачу и оплату, жители откликаются, заказчик выбирает исполнителя, стороны переписываются, после выполнения обе стороны подтверждают завершение. Только после двух подтверждений увеличивать счётчик выполненных заказов и разрешать отзыв. Предусмотри отмену, жалобу и спор.»

Промпт 5 — профиль и приватность:
«Сделай профиль с именем, аватаром, обложкой, статусом/описанием, публичным районом, объявлениями, выполненными заказами и отзывами. Не показывай точный домашний адрес публично. Точный адрес заказа может быть раскрыт только выбранному исполнителю по явному согласию пользователя и только на период выполнения задания.»

Промпт 6 — авторизация:
«Подключи настоящую серверную авторизацию. Нужны email с подтверждением, восстановление пароля, телефон через SMS OTP, Google OAuth и VK ID при доступности провайдера. Секреты держать только на сервере. Добавить rate limiting, безопасные сессии, защиту от перебора, проверку OAuth state/PKCE и возможность удалить аккаунт. Не изображать вход как работающий, пока провайдер реально не настроен.»

Промпт 7 — сообщения:
«Реализуй приватные диалоги между разными зарегистрированными пользователями. Доступ к истории только у участников. Нужны список чатов, отправка и получение сообщений, время, непрочитанные, пагинация и realtime через WebSocket/SSE. Добавь жалобу/блокировку собеседника. Не использовать общие демонстрационные диалоги.»

Промпт 8 — «Наш Амурск»:
«Создай городской культурно-исторический раздел “Наш Амурск”: история города, хронология с проверяемыми источниками, фотогалерея города и архив жителей, воспоминания, подписи к фото с годом и районом, комментарии и модерация. Указывать источник и лицензию каждого изображения. Не выдумывать исторические факты и не брать фотографии без права использования.»

Промпт 9 — сервер и передача заказчику:
«Подготовь переносимый проект: фронтенд, backend API, PostgreSQL schema/migrations, Docker Compose, .env.example без секретов, инструкции запуска и деплоя, архитектурную схему, API reference, пользовательское руководство, backup/restore guide, security checklist, историю решений и промпты. Секреты не включать. Чётко перечислить что реально реализовано, что требует ключей/аккаунтов, что не интегрировано.»

Промпт 10 — проверка качества перед выдачей:
«Перед выдачей проверь синтаксис, сборку, ссылки, адаптивность, формы, API маршруты, авторизацию, права доступа к чужим диалогам, SQL ограничения, секреты в репозитории и Docker Compose. Выполни smoke tests. Не заявляй о тестах, которые не запускались. Подготовь список известных ограничений.»

7. РЕШЕНИЯ, КОТОРЫЕ НУЖНО УТОЧНИТЬ С ВЛАДЕЛЬЦЕМ

- Окончательное название, домен и логотип.
- Юридическое лицо/физлицо — оператор платформы и кто отвечает за персональные данные.
- Регион облака и фактическая стоимость по калькулятору Cloud.ru.
- Способ регистрации на первом запуске: email, SMS или оба.
- Какие районы Амурска будут доступны в фильтрах.
- Политика публикации старых фотографий, согласия авторов и модерация.
- Контакты поддержки и правила безопасных сделок.
